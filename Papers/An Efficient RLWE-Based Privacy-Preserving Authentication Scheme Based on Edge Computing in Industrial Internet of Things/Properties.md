# Authentication

Theorem 1: Suppose q is of the order Rq. Let PPT adversary A violate protocol P with at most qhash, qexe, qsend queries of the Hash, Execute and Send types, respectively. AdvRLW E A represents the probability that A finds a solution to the RLWE problem in polynomial time. The proposed anonymous mutual authentication technique is defined as provably secure if and only if the following conditions are satisfied as follows: AdvP (A) ≤ qh2ash 2κ + (qexe + qsend) q + (qexe + qsend)AdvRLW E A. Therefore, the proposed anonymous mutual-authentication protocol is secure when the RLWE problem is difficult to solve.

# Integrity

In Theorem 1, under the premise of RLWE, ki and kj are unforgeable for both sides of the communication. Therefore, whenever an adversary launches an attack and corrupts the integrity of the data, the other party can recognize it in time. During user authentication, as long as the attacker corrupts the data {P IDi, pi, wi, αi, ts1}, the ESj can determine whether the data is complete by comparing whether α′i = h(P IDi, pi, wi, σ′ i , ts1) it is equal to αi = h(P IDi, pi, wi, σi, ts1) or not. Similarly, during the edge server authentication process, as long as the adversary corrupts the data {IDj, pj, wj, αj, ts2}, the user can determine whether the data is complete by comparing whether the data α′j = h(IDj, pj, wj, σ′ j, ts2) is equal to αj = h(IDj, pj, wj, σj, ts2) or not. Thus, the proposed scheme guarantees data integrity.

# Mutual authentication

In step 2 of the authentication process, the ESj authenticates the SDi by checking whether α′i = h(P IDi, pi, wi, σ′ i , ts1) and αi = h(P IDi, pi, wi, σi, ts1) are equal. Because ESj knows P IDi and pi and acquires wi, σi and αi from the authentication message, it can verify the correctness of the message. In addition, since ki = (si + smi) · pmj, k′ i = (pi + pmi) · smj, one must possess the publicprivate key pair (smi, pmi) to obtain the same result σi as the ESj. If the SIVP does not assume that the problem can be solved in polynomial time, the corresponding private key cannot be obtained. Similarly, the SDi authenticates the legitimate edge server by comparing α′j = h(IDj, pj , wj, σ′ j , ts2) and αj = h(IDj, pj, wj, σj, ts2). Because SDi stores IDj, only if it has a public-private key pair (smj, pmj) can it compute the result σj equal to that computed by SDi. Therefore, our proposed mutual authentication scheme can guarantee mutual authentication on both sides of the communication.

# Anonymous

During the process of system registration, the SDi sends {IDi, P IDi} to the TA through a secure channel, and we assume that the TA is trusted; thus, only the SDi and the TA is aware of the IDi in the whole system. In the subsequent process, updating the user’s password does not require the participation of other participants. However, the user pseudo-identity update phase is updated through the public channel, and this process is used in the pseudo-identity. P IDi and IDi have no relevance; therefore, obtaining IDi through P IDi is impossible. Only by compromising the TA can an adversary obtain IDi. However, the TA is trusted and exchanges information through a secure channel, and the adversary cannot obtain IDi from it. Therefore, the proposed mutual authentication protocol satisfies the anonymity requirements.

# Session key establishment

In steps 2 and 3 of the authentication phase, the SDi and the ESj each independently calculate sk = h(P IDi, IDj, pi, wi, σi, αi, pj, wj, σj, αj) for the subsequent bulk data transmission. In the process of session key calculation, P IDi, IDj, pi and pj, these public parameters are needed and also need wi, σi, αi, wj, σj, and αj participate in the calculation. These parameters must be authenticated by both parties involved in the calculation and verified by each other to avoid the session key being determined by one party. Importantly, wi, σi, αi, wj, σj and αj are temporarily sampled and calculated each time such that the session key can be guaranteed to be different each time. Therefore, the proposed mutual authentication protocol satisfies session key establishment.

# Perfect forward secrecy

In the proposed scheme, both sides engage in negotiations on the shared key, containing some parameters that can be directly obtained from the open channel, and also some other parameters that are temporarily generated each time the session key is generated, such as si, ei, sj and ej, and other parameters calculated accordingly wi, σi, αi, wj, σj, and αj so on, to ensure the randomness of the session key. Therefore, although the adversary may obtain the previous session key, he/she cannot obtain the next session key. Simultaneously, we adopted the session key timing update policy to re-establish a new session key for the session key that has been used for a specified time. Therefore, the proposed mutual-authentication scheme guarantees perfect forward secrecy.
